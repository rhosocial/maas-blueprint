# 第 15 章 引擎选型与自研架构适配

> 引擎选型不是"哪个快"，而是"哪个能装下我的模型、我的运维能力和我的合规要求"。

## 15.1 选型判据

| 判据 | 权重 | 说明 |
|---|---|---|
| 架构覆盖 | 高 | 自研架构能否不改引擎就跑 |
| 量化支持 | 高 | FP8/INT4/AWQ/GPTQ，精度与吞吐 |
| 前缀缓存 | 高 | 多轮/Agent 场景的命脉 |
| 连续批处理 | 高 | 吞吐的基础 |
| LoRA 多租 | 中 | 多客户共享底座 |
| PD 分离 | 中 | 规模上去才需要 |
| 可观测性 | 中 | 是否暴露队列、KV、命中率 |
| 许可 | 高 | 商用条款、专利 |
| 运维复杂度 | 高 | 升级、调参、故障排查 |

## 15.2 三个主流引擎的适用面

| 引擎 | 优势 | 弱项 | 适用 |
|---|---|---|---|
| vLLM | 生态最广、模型覆盖快、社区活跃 | 高并发下的调度调优需要经验 | 通用 LLM 首选 |
| SGLang | 前缀缓存、结构化输出、复杂编排 | 生态相对小 | Agent、多轮、结构化 |
| TensorRT-LLM | NVIDIA 硬件上的极致性能 | 编译复杂、模型适配慢 | 追求极致成本、模型稳定 |

〔核验〕具体版本的能力与性能数字随发布变化，选型前用**自己的模型和流量**压测，
不要引用厂商 benchmark。

〔建议〕**生产只保留一个主引擎 + 一个备选引擎。** 同时维护三套引擎的镜像、调参、
监控和故障处理，是团队规模不允许的奢侈。

## 15.3 自研架构的三条适配路径

| 路径 | 做法 | 成本 | 风险 |
|---|---|---|---|
| 上游 PR | 把架构实现推进社区 | 前期高，长期低 | 评审周期不可控 |
| 插件/外挂 | 用引擎的扩展点注册自定义模型 | 中 | 扩展点可能不够用 |
| Fork | 维护自己的分支 | 低起步，高持续 | 与上游同步成本随时间指数上升 |

Fork 的真实成本：

```
每次上游发版：
  合并冲突（1~5 人天）
  + 回归测试（模型效果、前缀缓存隔离、性能基线）
  + 重新压测
  + 修复行为差异
```

如果每月发一次版，fork 至少吃掉 0.5 个全职人力，且会随时间恶化。

〔建议〕**优先上游 PR；扩展点够用就用插件；只有在"上游明确不接受 + 性能不可妥协"时才 fork，
并为 fork 设定退出条件（如上游合并后 3 个月内切回）。**

## 15.4 多模态与扩散引擎

| 能力 | 成熟度 | 备注 |
|---|---|---|
| 文本 LLM | 高 | 三大引擎都成熟 |
| 图像扩散 | 中 | 引擎支持参差，常需脚本化 |
| 视频扩散 | 低 | 多为研究代码，工程化程度低 |
| 多模态理解 | 中 | 编码器与 LLM 的拼接方式各异 |
| 音频 | 中 | 与视频管线耦合 |

〔核验〕扩散引擎的生态比 LLM 年轻 2~3 年，文档与接口稳定性都更差。给自研适配
留出的时间应按 LLM 的 2 倍估算。

## 15.5 引擎升级的回归清单

每次升级必须跑，缺一项不上线：

| 项 | 方法 | 通过标准 |
|---|---|---|
| 模型效果 | 固定题集，人工/自动评分 | 不低于基线 |
| 前缀缓存正确性 | 相同前缀不同后缀，验证输出 | 无串味 |
| 租户隔离 | 跨租户缓存测试 | 不命中他人缓存 |
| 性能 | 固定并发压测 | 吞吐/延迟不劣化 > 5% |
| 长上下文 | 最大上下文请求 | 不 OOM，不截断 |
| 工具调用 | 结构化输出解析 | 解析成功率不降 |
| 流式 | SSE 分块与结束符 | 无截断、无重复 |

## 15.6 选型决策记录

建议的 ADR 结构（附录 B 有模板）：

```
ADR-015 引擎选型
状态：提议 / 已接受 / 已废弃
背景：自研架构 X，需要前缀缓存与 LoRA
选项：vLLM / SGLang / TRT-LLM / fork
决定：以 vLLM 为主，SGLang 为备选
理由：架构覆盖 + 社区速度 + 可观测性
代价：高性能场景需自行调优；扩散另选引擎
复核时点：每季度 / 上游大版本 / 性能不达标时
```

## 本章结论

- 选型看"能否装下模型 + 能否运维"，不是看 benchmark 第一名。
- 自研架构优先上游 PR，其次插件，fork 要设退出条件。
- 生产只保留一个主引擎，避免运维爆炸。
- 升级回归要覆盖效果、缓存隔离、性能、工具调用四类。

## 决策点（结合自身情况）

1. 主引擎选 vLLM 还是 SGLang？取决于首个客户是通用对话还是 Agent。
2. 是否接受 fork？若接受，谁负责同步上游？
3. 扩散引擎自研适配的预算是多少？
