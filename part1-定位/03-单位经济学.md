# 第 3 章 单位经济学：一张卡能卖多少钱

> 不知道单位成本，就无法定价；无法定价，平台就只是一个成本中心。

## 3.1 成本结构

| 成本项 | 内容 | 量级特征 | 可控性 |
|---|---|---|---|
| 卡时 | GPU 采购/租赁、折旧、电、机房 | 最大项，随利用率摊薄 | 中（靠利用率） |
| 网络 | IB/RoCE 交换、跨区专线、出网带宽 | 视频业务出网是大头 | 中 |
| 存储 | 模型仓库、对象存储、日志 | 长期增长，易被忽略 | 高（生命周期策略） |
| 审核算力 | 文本审核、图像/视频抽帧审核 | 视频可占推理成本的 10%~20% | 中 |
| 人力 | 平台、引擎、SRE、合规、支持 | 固定成本，不随用量下降 | 低 |
| 合规 | 备案、评估、审计、法务 | 一次性 + 年度 | 低 |
| 失败重算 | 被抢占、超时、审核拒绝后的重跑 | 视频最显著 | 高（设计决定） |

## 3.2 三个公式

```
有效吞吐 = 理论吞吐 × 利用率 × 成功率
单位成本 = 卡时成本 ÷ 有效吞吐
毛利     = 单价 − 单位成本 − 变动成本（存储 / 出网 / 审核）
```

三个变量里，**利用率**最容易被高估。账面利用率按"卡被占用"算，但被占用的卡可能在
等数据、等编译、等权重加载，或者在跑一个 batch=1 的推理副本。真正该看的是
**有效吞吐 / 理论吞吐**（第 36 章给指标定义）。

## 3.3 三种计价单位

| 模态 | 计价单位 | 为什么 | 常见变体 |
|---|---|---|---|
| LLM | 百万 token（输入/输出/缓存分开） | 成本与 token 数近似线性 | 按上下文长度分档、按优先级加价 |
| 图像 | 张 × 分辨率 × 质量档 | 成本由像素与步数决定 | 批量折扣、商用授权加价 |
| 视频 | 秒 × 分辨率（含音频） | 成本由时长与分辨率决定 | 参考素材另计、失败退款 |

不能用"卡时"直接卖给客户：客户不理解，也无法为闲置付费（除非是独占部署）。
卡时是**内部核算单位**，不是**对外计价单位**。

## 3.4 四种售卖形态

| 形态 | 适合客户 | 收入特征 | 架构要求 |
|---|---|---|---|
| 按量 | 中小客户、试水 | 波动大，毛利高 | 精确计量、实时限额 |
| 承诺吞吐 | 中大型客户 | 稳定，可预测 | 容量预留、隔离、SLA |
| 独占部署 | 大客户、强隔离 | 单价高，利用率风险转移 | 专属副本、独立升级窗口 |
| 批价/填谷 | 价格敏感、可等待 | 低毛利，提升利用率 | 低优先级队列、可中断 |

〔建议〕四种都要有，但**第一版只做按量 + 批价**。承诺吞吐和独占部署需要容量预留与
SLA 赔付能力，过早做会把有限的容量锁死。

## 3.5 示例测算（示意，非报价）

以下数字用于校验数量级，实际必须用采购价、实测吞吐和真实利用率重算。

**LLM（70B 级，FP8，8×H100，TP=8）**

```
卡时成本     8 卡 × 20 元/卡时 = 160 元/小时
实测输出     3000 tok/s（较大 batch）
利用率       60%
成功率       99%
有效输出     3000 × 0.6 × 0.99 = 1782 tok/s = 6.42 M tok/h
单位成本     160 ÷ 6.42 ≈ 24.9 元 / 百万输出 token
```

**图像（1024×1024，30 步，单卡）**

```
单张耗时     8 GPU 秒 → 理论 450 张/小时
利用率       50% → 225 张/小时
单位成本     20 ÷ 225 ≈ 0.089 元/张（含审核与存储约 0.11 元/张）
```

**视频（720p，5 秒，8 卡并行约 3 分钟）**

```
单条卡时     8 卡 × 3 分钟 = 0.4 卡时 → 8 元
利用率       50% → 16 元 / 5 秒 = 3.2 元/秒
含抽帧审核、转码、出网，约 3.8 元/秒
```

三个结论：

1. LLM 的成本对**利用率**极其敏感：利用率从 60% 掉到 30%，单位成本直接翻倍。
2. 图像的成本对**批量**敏感：单张请求占满卡但 batch=1，等于把利用率打对折。
3. 视频的成本对**失败重算**敏感：一次失败的 5 分钟任务，等于白烧 8 元。

## 3.6 七个定价陷阱

| 陷阱 | 后果 | 应对 |
|---|---|---|
| 缓存命中与未命中同价 | 客户没有动力复用，平台也失去优化收益 | 缓存命中单独计价，通常为输入价的 10%~25% |
| 长上下文按线性计价 | 注意力成本超线性，越长越亏 | 按上下文长度分档，或对超长请求单独报价 |
| 失败/重试免费 | 被恶意重试放大成本 | 明确"平台原因免费、客户原因计费" |
| 免费额度无上限 | 被刷量 | 额度 + 速率 + 实名三重限制 |
| 视频失败全额退但已消耗算力 | 重算成本全由平台承担 | 预扣 + 按阶段退款，或对"已生成部分"计费 |
| 出网带宽未计入 | 视频下载把毛利吃光 | 交付走对象存储，出网单独计价或限额 |
| 审核成本未计入 | 视频抽帧审核可能比生成还贵 | 把审核算进档位价格 |

## 3.7 保本点

固定成本（人力 + 平台 + 机房基础）决定了一个**最低收入规模**：

```
保本收入 = 固定成本 ÷ 毛利率
所需有效吞吐 = 保本收入 ÷ 单价
```

举例（示意）：固定成本 1000 万/年，目标毛利 35%，则需收入约 2857 万/年。
若平均单价 50 元/百万 token，需要约 571 亿 token/年，折合平均 1.8 万 tok/s 的持续输出。
这个数字应该让所有人清醒：**MaaS 的生意门槛在"持续吞吐"，不在"峰值 demo"**。

## 3.8 本章结论

- 卡时是内部核算单位，token / 张 / 秒才是对外计价单位。
- 利用率是最大的杠杆，但不是唯一杠杆；失败重算和审核成本常被漏算。
- 先算清 LLM（最成熟、最可预测），再谈图像，最后谈视频（方差最大）。
- 视频应卖"秒产能"，并承诺排队时长，而不是承诺低延迟。

## 决策点（结合自身情况）

1. 对外定价的第一版采用哪两个单位？建议：LLM 按 token（输入/输出/缓存三档），视频按秒。
2. 是否对缓存命中单独计价？若不做，第 16 章的路由优化就没有商业回报。
3. 免费额度的上限与滥用处置流程由谁负责？
